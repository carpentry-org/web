SSE

defn

(Fn [App, String, (Fn [(Ref SSEEvent a), (Ref (Map String String) b), (Ref SSEStream c)] ())] App) 

                        (SSE app pattern handler)

adds a Server-Sent Events route. A GET to pattern is answered with a text/event-stream body that stays open, and the handler is called for each lifecycle event (SSEEvent): Connect, Tick and Close.

Tick fires every App.sse-tick-interval seconds; when it queues nothing, a comment line goes out instead so idle streams survive proxies. Server-Sent Events are one-way, so anything the client writes to the stream is ignored.

(defn clock [event params s]
  (match-ref event
    (SSEEvent.Connect) (SSEStream.send-event s "ready" "")
    (SSEEvent.Tick) (SSEStream.send s &(Int.str (System.time)))
    (SSEEvent.Close) ()))

(defserver "0.0.0.0" 3000
  (SSE "/events" clock))

WS

defn

(Fn [App, String, (Fn [(Ref WSEvent a), (Ref (Map String String) b), (Ref WebSocket c)] ())] App) 

                        (WS app pattern handler)

adds a WebSocket route. The handler is called for each lifecycle event (WSEvent): Connect, Message, Binary, and Close.

(defn echo [event params ws]
  (match-ref event
    (WSEvent.Connect) (WebSocket.send ws @"connected")
    (WSEvent.Message msg) (WebSocket.send ws (fmt "echo: %s" msg))
    (WSEvent.Binary data) (WebSocket.send-binary ws data)
    (WSEvent.Close) ()))

(defserver "0.0.0.0" 3000
  (WS "/ws/echo" echo))

WSP

defn

(Fn [App, String, (Array String), (Fn [(Ref WSEvent a), (Ref (Map String String) b), (Ref WebSocket c)] ())] App) 

                        (WSP app pattern protocols handler)

adds a WebSocket route with subprotocol negotiation.

The protocols array lists the subprotocols this route supports (RFC 6455 §4.2.2). During the upgrade handshake, the server selects the first client-requested protocol that appears in this list and includes it in the Sec-WebSocket-Protocol response header. The negotiated protocol is available via (WebSocket.protocol ws).

(defn chat [event params ws]
  (match-ref event
    (WSEvent.Connect)
      (match-ref (WebSocket.protocol ws)
        (Maybe.Just p) (WebSocket.send ws (fmt "using protocol %s" p))
        (Maybe.Nothing) (WebSocket.send ws @"no subprotocol"))
    _ ()))

(defserver "0.0.0.0" 3000
  (WSP "/ws/chat" [@"chat-v2" @"chat-v1"] chat))

serve

defn

(Fn [(Ref App a), (Ref (Array (Fn [(Ref Request b), (Ref (Map String String) c)] (Maybe Response) d)) a), (Ref (Array (Fn [(Ref Request e), (Ref (Map String String) f), Response] Response g)) a), (Ref String h), Int] ()) 

                        (serve app before-hooks after-hooks host port)

starts the web server on host:port.

Uses kqueue/epoll for concurrent connection handling with HTTP keep-alive. Sockets are non-blocking, reads accumulate into a per-connection buffer, and writes drain across writable events.

The loop is single-threaded, so peak throughput is bounded by one core. For multi-core scaling, see serve-with-workers.

serve-with-workers

defn

(Fn [(Ref App a), (Ref (Array (Fn [(Ref Request b), (Ref (Map String String) c)] (Maybe Response) d)) a), (Ref (Array (Fn [(Ref Request e), (Ref (Map String String) f), Response] Response g)) a), (Ref String h), Int, Int] ()) 

                        (serve-with-workers app before-hooks after-hooks host port n)

starts n worker processes, each running its own event loop bound to host:port. The kernel distributes incoming connections across workers via SO_REUSEPORT (Linux 3.9+, most BSDs).

Falls back to single-process serve when n is 1 or less.

(App.serve-with-workers &app &bh &ah "0.0.0.0" 3000 4)

Or via defserver:

(defserver "0.0.0.0" 3000
  (workers 4)
  (GET "/" handler))
